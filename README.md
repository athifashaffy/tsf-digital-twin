# TSF Digital Twin

A digital twin and hardware kit for a lab-scale **tailings storage facility (TSF)** monitoring prototype: low-cost IoT sensors stream water level, outflow and turbidity from an Arduino to a Python server, and gradient-boosted models forecast the next minutes so an alarm can fire **before** a limit is crossed.

The prototype and forecasting framework come from the MSc thesis *AI-Driven IoT-Based Monitoring and Predictive Framework for Tailings Flow Behaviour* (Md Rashed Azad Chowdhury, Laurentian University, 2026). The thesis document, slides and raw experiment data are **not** part of this repository.

## What's here

| Folder | Contents |
|---|---|
| `booth/` | 3D digital twin (`index.html`, operations console) and a cinematic booth loop (`showcase.html`). Built from `tsf-digital-twin.html` with `build.py`. |
| `firmware/tsf_node/` | Arduino UNO R4 WiFi firmware: HC-SR04 level, YF-S201 flow, SEN0189 turbidity, water-level strip, 16×2 I²C LCD, buzzer, optional IR mute. Posts JSON to the server every second. |
| `firmware/diag/`, `firmware/i2cfind/` | Wiring finder and I²C scanner sketches used to debug the rig. |
| `firmware/board.py` | Send commands to the board over USB (`STATUS`, `SCAN`, `WIFI:name\|pass`, `SERVER:ip:port`). |
| `hardware/print/` | Printable parts (STL) for the electronics box, bar mounts, sensor holders and flow-meter cradle, generated by `make_parts.py`; `viewer.html` previews the assembly. |
| `DATA Server/` | FastAPI ingestion server (`live_server.py`), Streamlit dashboard, training scripts and trained XGBoost models. |

## Run it

**Digital twin** (no hardware needed):

```sh
cd booth
python3 -m http.server 8600
# console:  http://localhost:8600/
# showcase: http://localhost:8600/showcase.html   (F = full screen, ← → = chapters)
```

The pages load three.js and fonts from a CDN, so they need an internet connection.

**Live sensors**:

```sh
python3 -m venv .venv && .venv/bin/pip install fastapi uvicorn pandas pyserial
cd "DATA Server" && ../.venv/bin/uvicorn live_server:app --host 0.0.0.0 --port 8502
```

Flash `firmware/tsf_node` (Arduino IDE or `arduino-cli`, board `arduino:renesas_uno:unor4wifi`, library *LiquidCrystal I2C*), then set Wi-Fi and the server address over USB:

```sh
.venv/bin/python firmware/board.py "WIFI:YourNetwork|YourPassword" "SERVER:<laptop-ip>:8502" STATUS
```

Open the twin, switch to **Live sensors**, and the 3D model follows the real readings; sensors without valid data are shown as offline.

## Wiring (firmware pin map)

| Pin | Connection |
|---|---|
| D2 | YF-S201 signal (interrupt) |
| D5 / D6 | HC-SR04 TRIG / ECHO |
| D7 | IR receiver (optional) |
| D8 | Buzzer |
| D9 | Water-level strip VCC (pulsed) |
| A0 | SEN0189 turbidity board (analog mode) |
| A1 | Water-level strip signal |
| SDA / SCL | LCD I²C backpack |
| 5V / GND | Breadboard rails — sensors and LCD (not VIN when powered from USB) |

## Notes

- The showcase and the console's Simulation mode replay the thesis test scenarios (steady inflow, storm inflow, blocked decant, sediment pulse) with a tank mass-balance model; the forecast shown is a 7-minute trend projection standing in for the trained models. Pages are labelled as simulated.
- 3D-print dimensions for bought parts are datasheet values — measure your parts and edit the constants at the top of `hardware/print/make_parts.py`.
